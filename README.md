# Lodestar

ИИ-кампус для вуза: ИИ-навигатор ведёт студента к знаниям лестницей подсказок, а не пишет работу за него.

## Устройство

| Папка | Что внутри |
| --- | --- |
| `app/` | Приложение на Flutter для всех платформ и ролей |
| `server/` | Сервер на Go: ядро и модули в одной программе |
| `contracts/` | Контракт API (OpenAPI) и схемы событий |
| `deploy/` | Установка: Docker Compose для пилота |
| `docs/adr/` | Записи архитектурных решений |

## Быстрый старт

```sh
cp deploy/.env.example deploy/.env
make up
```

В `deploy/.env` впишите `LODESTAR_SECRET_KEY`, его выдаёт `openssl rand -base64 32`.

Сервер поднимается на `http://localhost:8080`, проверка: `curl localhost:8080/healthz`.

## Подключить вуз

```sh
docker compose -f deploy/compose.yaml exec server /lodestarctl tenant create -slug kaznu -name "КазНУ"
docker compose -f deploy/compose.yaml exec -e LODESTAR_OIDC_CLIENT_SECRET=... server \
  /lodestarctl oidc set -tenant kaznu -key microsoft -name "Microsoft" -issuer https://login.microsoftonline.com/<id>/v2.0 -client-id <id>
```

Команда напечатает адрес возврата, его нужно указать в настройках приложения у провайдера. Когда администратор вуза войдёт первый раз, выдайте ему высшую роль:

```sh
docker compose -f deploy/compose.yaml exec server /lodestarctl role grant-top -tenant kaznu -email admin@kaznu.kz
```

## Режим тестировщика

Чтобы погонять Lodestar самому, без настройки входа вуза, нужен только Docker. Установщик сам создаст `deploy/.env` с паролями, соберёт веб-версию, поднимет ИИ-навигатор на Ollama, звонки на LiveKit и почтовый ящик Mailpit.

```sh
./install-tester.sh          # macOS и Linux
install-tester.cmd           # Windows, можно двойным щелчком
```

Первый запуск занимает 15–30 минут. Повторный запуск обновляет адрес компьютера в сети и перезапускает всё. Параметры: `--no-ai` и `--no-calls` (в Windows `-NoAi`, `-NoCalls`), `--model=qwen2.5:7b` (`-Model`) для модели посильнее.

- Веб-версия: `http://localhost:8080`, код вуза `demo`. С телефона в той же Wi-Fi: `http://<IP компьютера>:8080`, установщик его напечатает.
- На экране входа раздел «Режим тестировщика»: вход за студентку, студента, преподавателя или администратора одной кнопкой, без пароля. В профиле тот же раздел меняет пользователя.
- Письма не уходят наружу, их видно в Mailpit: `http://localhost:8025`.
- Модель по умолчанию `qwen2.5:3b` работает на процессоре, нужно 8 ГБ памяти. Для Ollama нужно ещё около 4 ГБ на диске.
- Остановить: `make tester-down`. Запустить снова без установщика: `make tester`.

Режим пускает кого угодно без пароля. Не включайте его у настоящего вуза.

### На своём сервере для общего теста

Нужен сервер на Linux с публичным IP и уже установленным Docker (с плагином compose), от 4 ядер, 8 ГБ памяти и 30 ГБ диска. Под root или пользователем из группы `docker`:

```sh
git clone https://github.com/babakapaa/Lodestar.git && cd Lodestar
./install-tester.sh --server
```

- Настройки сервера установщик не меняет: не ставит пакеты, не трогает файрвол и SSH. Если чего-то не хватает (Docker, память, диск, открытые порты), он пишет предупреждение и итоговый список в конце.
- Адрес получится вида `https://1-2-3-4.sslip.io`: сервис sslip.io превращает IP в имя. HTTPS даёт nginx в контейнере, сертификат Let's Encrypt выпускает и продлевает certbot. Свой домен: `--domain=lodestar.example.kz`, у домена и поддоменов `s3.` и `mail.` (со звонками ещё `rtc.`) должна быть A-запись на IP сервера.
- Если порты 80 и 443 уже заняты (например, своим nginx), установщик сам переходит в режим `--proxy=host`: Lodestar слушает только `127.0.0.1`, а установщик готовит конфиг `deploy/nginx/rendered/lodestar.conf` для `include` и подсказывает, какой сертификат выпустить. Занятые локальные порты (8080, 9000, 8025, 7880) он обходит сам и сохраняет выбранные в `deploy/.env`. Контейнеры называются `lodestar-*`, чужие проекты не задеваются.
- Снаружи должны быть открыты 80 и 443. Открывает их администратор сервера.
- Звонки на сервере по умолчанию выключены. Включить: `--calls`, тогда нужны ещё 7881/tcp и 50000–50200/udp, и голос с видео идут напрямую на IP сервера, минуя Cloudflare и подобные прокси. Выбор установщик запоминает.
- ИИ-навигатор: модели `qwen2.5:3b` и `bge-m3`, вместе около 3 ГБ на диске, памяти контейнер берёт не больше 5 ГБ (`LODESTAR_AI_MEMORY` в `deploy/.env`).
- Веб-версия по адресу сервера, код вуза `demo`. В приложении для Windows: «Сменить вуз» на экране входа и адрес сервера. Сборку с уже вшитым адресом можно запустить в Actions → Desktop → Run workflow, поле «Адрес сервера».
- Письма: `https://mail.<адрес>`, логин `tester`, пароль установщик напечатает и сохранит в `deploy/.env`.
- Обновить после `git pull`: снова `./install-tester.sh`, режим сервера он запомнит. Вернуть локальный режим: `--local`.
- В тестовом вузе уже есть курс с двумя заданиями (эссе с картой поиска и защитой, командный проект), материалы лекций для навигатора, расписание, задача лиги, канал курса, группа и личная переписка.

## Тестовый вуз

Для показа и приёмки есть тестовый вуз `demo` со своим входом без паролей: студентка, преподаватель и администратор. Его нельзя включать у настоящего вуза.

В `deploy/.env` впишите `DEMO_IDP_CLIENT_SECRET` (любая длинная строка) и `DEMO_IDP_ISSUER`. Это адрес демо-входа, который открывается и с телефона, и с сервера, например `http://192.168.1.10:8090`. `LODESTAR_PUBLIC_URL` должен открываться с телефона так же.

```sh
docker compose -f deploy/compose.yaml --profile demo up -d
docker compose -f deploy/compose.yaml exec -e LODESTAR_OIDC_CLIENT_SECRET=$DEMO_IDP_CLIENT_SECRET server \
  /lodestarctl demo seed -issuer $DEMO_IDP_ISSUER
```

В приложении укажите адрес сервера и код вуза `demo`, нажмите «Войти через Демо-вход» и выберите, кем войти.

В тестовом вузе уже есть курс «Основы биологии» (BIO-101): группа ДЕМО-21 со студенткой, преподаватель, опубликованное задание со сроком через пять дней и пары по понедельникам и средам.
