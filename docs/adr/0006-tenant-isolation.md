# 0006. Разделение данных вузов в одной базе

Дата: 2026-11-12. Статус: принято.

## Решение

Один сервер может обслуживать несколько вузов. Данные вуза отделяются на уровне базы через row level security PostgreSQL, а не только проверками в коде.

## Как устроено

- Список вузов лежит в `core.tenants`.
- У каждой таблицы с данными вуза есть столбец `tenant_id`, включены `ENABLE` и `FORCE ROW LEVEL SECURITY` и политика `tenant_id = current_setting('lodestar.tenant')::uuid`.
- Запросы к таким таблицам идут только через `database.TenantTx`: транзакция переключается на роль `lodestar_app` и выставляет текущий вуз. Даже ошибка в коде модуля не вернёт чужие данные.
- Роль `lodestar_app` создаётся при первой миграции и не умеет входить в базу. Права на таблицы модуль выдаёт ей в своей миграции.

## Почему

Ошибка в одном запросе не должна стать утечкой данных другого вуза. Проверка в базе ловит её всегда.

## Отвергнуто

Отдельная база на каждый вуз: тяжелее обновлять и обслуживать, а вуз, которому нужна своя база, и так ставит свой сервер.
