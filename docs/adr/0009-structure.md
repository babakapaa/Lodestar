# 0009. Структура вуза деревом

Дата: 2026-11-12. Статус: принято.

## Решение

Структура вуза — одно дерево подразделений. Вид подразделения (`faculty`, `department`, `stream`, `group` и любой другой) вуз выбирает сам, жёсткой схемы «факультет → кафедра → группа» нет.

## Как устроено

- `core.units` хранит дерево через `parent_id`. У подразделения есть `code` из системы вуза, по нему работает импорт.
- Участники лежат в `core.unit_members`. Что человек делает в подразделении, решают роли: роль выдаётся на область `unit:<id>` и действует во всём, что внутри.
- Цепочку областей для прав даёт `structure.Tree`: вуз → корень → … → подразделение. Это заменяет плоскую цепочку из [0008](0008-roles.md), поэтому декан с правом `core.structure.manage` на своём факультете управляет только им.
- Подразделения не удаляются, а уходят в архив вместе со всем внутри. Данные и история сохраняются.
- История в `core.unit_events` только дописывается: у роли приложения нет прав менять или удалять записи.
- Импорт из CSV идёт одной транзакцией: если в файле есть ошибки, не сохраняется ничего, а в ответе номера строк и коды ошибок.

## Почему

Вузы устроены по-разному: где-то институты вместо факультетов, где-то нет кафедр. Дерево с видами от вуза покрывает всё это без доработок.
