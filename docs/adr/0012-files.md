# 0012. Файлы в хранилище вуза

Дата: 2026-11-12. Статус: принято.

## Решение

Файлы лежат в S3-совместимом хранилище вуза (MinIO из комплекта или любое другое). Содержимое идёт напрямую между приложением и хранилищем по подписанным ссылкам, сервер Lodestar хранит только сведения о файле.

## Как устроено

- `POST /v1/files` создаёт запись со статусом `pending` и отдаёт ссылку на загрузку на 15 минут. В подпись входят тип и точный размер, поэтому загрузить другое не получится.
- После загрузки приложение вызывает `POST /v1/files/{id}/complete`. Сервер сверяет размер в хранилище и ставит статус `ready`.
- `GET /v1/files/{id}/download` отдаёт ссылку на скачивание на 5 минут с настоящим именем файла.
- Объект хранится под ключом `<вуз>/<файл>`. Загрузки, которые не завершили за сутки, удаляются вместе с содержимым.
- Наибольший размер файла задаёт вуз настройкой `core.files.max_file_mb`, по умолчанию 1024 МБ. Общих квот ядро не вводит.
- Пока файл видит и удаляет только владелец. Модули будут давать доступ к файлам, прикреплённым к своим объектам (сдаче работы, сообщению), отдельной частью.
- Без `LODESTAR_S3_ENDPOINT` сервер работает, а запросы к файлам отвечают 503 `files_unavailable`.

## Настройка

`LODESTAR_S3_ENDPOINT` — адрес хранилища для сервера, `LODESTAR_S3_PUBLIC_ENDPOINT` — адрес, по которому до него доходят приложения, `LODESTAR_S3_REGION`, `LODESTAR_S3_BUCKET`, `LODESTAR_S3_ACCESS_KEY`, `LODESTAR_S3_SECRET_KEY`. Корзина создаётся при запуске, если её нет.

## Почему

Через сервер не проходят гигабайты видео и датасетов, поэтому он не упирается в сеть и память. Вуз сам выбирает, где лежат данные, что важно для законов о данных.
