# 0014. Общий поиск

Дата: 2026-11-12. Статус: принято.

## Решение

Одна строка поиска ищет сразу везде: людей, подразделения и объекты модулей. Общего индекса нет: каждый источник ищет в своих таблицах и сам решает, что человек вправе видеть. Ядро только собирает ответы и сортирует их по близости.

## Как устроено

- Источник (`search.Source`) — вид (`people`, `units`, у модуля `<модуль>.<вид>`) и функция поиска внутри транзакции вуза. Модуль отдаёт свои источники через `SearchSources()`. Вид чужого модуля зарегистрировать нельзя.
- Если модуль выключен, его источники не опрашиваются и не показываются в `GET /v1/search/kinds`.
- Ядро ищет людей по имени из системы входа и по имени из профиля, подразделения по названию и коду. Архивные подразделения не находятся.
- Поиск по триграммам (`pg_trgm`): находит по части слова и с опечатками, одинаково работает для казахского, русского и английского, без словарей. «Ё» и «е» считаются одной буквой (`core.search_norm`).
- В ответе только название, подпись и ссылка. Сервер не хранит, кто что искал.

## Почему

Отдельный индекс пришлось бы синхронизировать с данными и правами каждого модуля, и любая ошибка показала бы лишнее. Когда источник проверяет права там же, где хранит данные, такой ошибки быть не может. Если данных станет много, источник модуля может перейти на свой индекс, не меняя API.
