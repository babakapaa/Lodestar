# 0017. Вход в приложении

Дата: 2026-11-12. Статус: принято.

## Решение

Приложение одно для всех вузов. При первом запуске человек вводит адрес сервера и код вуза, затем входит через способ, который подключил вуз. Вуз может собрать свою версию приложения с заранее заданным адресом.

## Как устроено

- Адрес сервера и код вуза хранятся в настройках устройства. Сборка с `--dart-define=LODESTAR_SERVER=… --dart-define=LODESTAR_TENANT=…` подставляет их сама.
- Вход: приложение создаёт PKCE, открывает `/v1/auth/{tenant}/{provider}/login` в системном браузере (`flutter_web_auth_2`) и меняет одноразовый код на пару токенов. Пароль вуза приложение не видит.
- Адреса возврата: `io.github.babakapaa.lodestar:/auth` на телефонах и macOS, `http://localhost:43823/auth` на Windows и Linux, `<адрес сайта>/auth.html` в вебе. Первые два сервер разрешает по умолчанию, адрес сайта вуз добавляет в `LODESTAR_APP_REDIRECTS`.
- Токены лежат в защищённом хранилище системы (`flutter_secure_storage`). Клиент API сам обновляет токен доступа при ответе 401, один раз на все параллельные запросы. Если обновить не удалось, приложение возвращается на экран входа.
- Пока человек не вошёл, доступны только подключение, вход и настройки внешнего вида и языка.
- Профиль: имя, о себе, контакты с выбором, кому они видны, список устройств с выходом на любом из них и выход на этом устройстве.

## Почему

Вузы ставят свои серверы, поэтому приложение не может знать адрес заранее. Вход через браузер и PKCE не даёт приложению пароль и работает с любым провайдером вуза.
