# 0019. Тестовый вуз и администрирование в приложении

Дата: 2026-11-12. Статус: принято.

## Решение

Для показа и приёмки есть тестовый вуз `demo` со своим входом без паролей. Администратор вуза настраивает вуз, модули и смотрит журнал действий прямо в приложении.

## Как устроено

- `lodestar-demo-idp` это маленький OIDC-провайдер. Он показывает страницу «кем войти» с тремя людьми: студентка, преподаватель, администратор. Он отдаёт коды только на адреса из `DEMO_IDP_REDIRECTS`, коды одноразовые и живут 5 минут, ключ подписи создаётся при каждом запуске. В Docker Compose он включается только профилем `demo`.
- `lodestarctl demo seed` создаёт вуз `demo`, подключает к нему демо-вход, заводит трёх людей и выдаёт роли: администратору высшую, преподавателю роль «Преподаватель» с правом вести состав групп. Команду можно запускать повторно.
- Тот же провайдер работает в тестах сервера вместо отдельной копии кода.
- Приложение берёт права из `GET /v1/me/permissions` и показывает только то, что человеку можно. «Администрирование» видно при праве на настройки вуза или на журнал.
- Настройки вуза строятся по схеме с сервера: переключатель, выбор из списка, число с границами, текст. Названия настроек ядра переведены в приложении, для настроек модулей пока показывается ключ.

## Что дальше

Роли, назначения и подразделения в приложении. Названия и подсказки настроек модулей должны приходить с сервера вместе со схемой, как названия типов уведомлений.

## Почему

Приёмка ядра по ТЗ требует, чтобы студент, преподаватель и админ вошли через тестовый вуз и увидели разное. Настоящий провайдер вуза для этого не нужен, а отдельный демо-вход нельзя случайно включить в основной сервер.
