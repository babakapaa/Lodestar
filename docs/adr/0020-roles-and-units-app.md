# 0020. Роли и подразделения в приложении

Дата: 2026-11-12. Статус: принято.

## Решение

Администратор вуза ведёт роли, выдаёт их людям и строит структуру вуза прямо в приложении. Преподаватель с правом вести состав групп видит подразделения и меняет только состав.

## Как устроено

- «Роли»: список по старшинству, роль выше управляет ролями ниже. Порядок меняется перетаскиванием, приложение отправляет новую позицию, а проверку старшинства делает сервер. У роли есть название, цвет и права из `GET /v1/permissions`. Роль по умолчанию нельзя переименовать или удалить.
- «Люди и роли»: поиск человека через `GET /v1/search?kind=people`, затем его роли, выдача и отзыв.
- «Подразделения»: дерево по уровням. Типы факультет, кафедра, поток и группа переведены, другие типы вуза показываются как есть. Подразделение можно изменить, перенести, убрать в архив и вернуть. На странице подразделения виден его состав.
- «Администрирование» видно при любом из прав: настройки, журнал, роли, структура, состав групп. Каждый пункт внутри показывается только при своём праве.
- Ошибки сервера про старшинство ролей, чужие права, занятый код и перенос внутрь себя показываются понятным текстом на трёх языках.

## Что дальше

Этап 2 «Учёба». Выдача роли на подразделение и срок роли пока задаются через API, в приложении выдаётся роль на весь вуз.

## Почему

Так ядро закрыто целиком: вуз настраивается без консоли, а приложение ничего не решает за вуз и только показывает то, что разрешил сервер.
