# 0030. Личная база источников

Дата: 2026-11-12. Статус: принято.

## Решение

Источники студента живут в модуле заметок: таблица `notes.sources`, поля описания запечатаны тем же ключом, что и заметки, а место считается в ту же квоту. Источник видит только владелец. id создаёт устройство, поэтому источник можно добавить без сети, повтор сохранения с тем же id обновляет запись.

- `GET /v1/notes/sources`, `POST /v1/notes/sources`, `DELETE /v1/notes/sources/{id}`.
- `POST /v1/notes/lookup` заполняет описание по DOI (Crossref) или по ссылке (метаданные страницы `citation_*`, Dublin Core, Open Graph). Результат не сохраняется: студент проверяет и правит его сам.
- К источнику можно привязать свой файл из `core/files`, например PDF. Чужой файл привязать нельзя.
- Сервер ходит наружу только через `safehttp`: клиент отказывается соединяться с адресами внутренних сетей, ограничивает время, размер ответа и число переадресаций. Так ссылка от студента не откроет внутренние сервисы вуза. Клиент передаётся модулям в `module.Kernel.Outbound`.
- Пути под `/v1/notes/`, потому что модуль получает только свой префикс. Пути выбраны так, чтобы не пересекаться с путями заметок в `ServeMux`.
- Библиографическая запись по ГОСТ собирается в приложении из полей источника.

## Исправлено попутно

Реестр модулей монтировал только `/v1/{module}/`, поэтому `GET /v1/notes` и `POST /v1/notes` получали переадресацию и 404. Теперь монтируется и корень модуля.

## Почему

Разбор, решение 3.4: источник добавляется по ссылке, DOI или файлу, запись по ГОСТ собирается сама, свои источники помечаются «не проверен библиотекой».
