# 0040. Защиты на сервере

Дата: 2026-11-13. Статус: принято.

## Решение

- **Где живёт.** Защиты входят в модуль `study`: им нужны задание, список курса и оценки, которые принадлежат этому модулю. Новый код лежит в файлах `defense_*`, а логика выставления оценки вынесена в общий метод, чтобы оценка с защиты и обычная оценка шли одним путём (журнал, уведомление).
- **Формат.** У задания есть поле `defense`: `full` (полная для всех), `short` (короткая для всех) или `sample` (полная для выбранных). Пусто, если защиты нет. Кого выбрать для `sample`, решает преподаватель: вручную или случайно. Списков «подозрительных» система не составляет.
- **Запись.** Преподаватель создаёт время пачкой: начало, длина, место, вместимость, количество. Студент записывается сам и может перейти на другое время или отменить запись до начала. Если преподаватель удаляет время, записавшиеся получают уведомление.
- **Вопросы и протокол.** Вопросы бывают четырёх видов: понимание, анализ, применение и путь поиска. У каждого вопроса есть отметка понимания по шкале 0–3 и заметка. До защиты студент не видит вопросы. После завершения он видит протокол целиком, и протокол попадает в выгрузку его данных.
- **Оценка.** «Завершить защиту» закрепляет статус (`held` или `missed`) и в той же транзакции может сохранить оценку. Так отчёт о защите и оценка не расходятся.
- **Запись защит.** Записывать ли защиты, решает вуз настройкой `study.defense_recording` (по умолчанию выключено). Студент видит это заранее.
