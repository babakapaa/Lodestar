# 0045. Лига на сервере

Дата: 2026-11-13. Статус: принято.

## Решение

- **Отдельный модуль `league`.** Лига идёт внутри списка, у которого есть источник оценок (`module.ScoreSource`). Учёба отдаёт `study.course`: опубликованные задания с оценкой и результаты студентов. Если в задании есть защита, результат засчитывается только после проведённой защиты (при выборочной защите и тем, кого не выбрали). Состав лиги и преподаватели берутся из того же списка курса. Лига создаётся при первом обращении, без настройки.
- **Баллы по видимой формуле.** У каждой работы есть вес: сколько баллов она даёт за максимальную оценку. По умолчанию проектная работа (командная или с защитой) даёт 100, остальные 0. Баллы = оценка / максимум × вес. Формулу видят и преподаватель, и студенты, менять её может преподаватель. У каждого начисления видна причина: работа, оценка, максимум и вес, или текст ручного начисления. За активность баллов нет.
- **Сезоны.** Начисление принадлежит сезону, в котором появилось. После закрытия сезона его начисления не меняются, даже если оценку исправили. Новый сезон начинается с нуля баллов, дивизион сохраняется. Рост считается к прошлому сезону, в каждом дивизионе отмечается самый большой рост.
- **Дивизионы и переходы.** Преподаватель задаёт от 1 до 10 дивизионов с границами в баллах, по умолчанию три: 0, 150 и 300. В первом сезоне все в нижнем. Вверх студент переходит сразу по достижении границы, вниз только при закрытии сезона. Преподаватель выбирает: переходы применяются сами или ждут подтверждения. Отклонённый или отменённый переход не предлагается снова в том же сезоне, пока студент не наберёт на дивизион выше.
- **Видимость.** Общего рейтинга нет. Студент видит свои баллы, дивизион, сколько осталось до следующего и таблицу своего дивизиона. В таблице можно скрыть имя («Участник») или показать никнейм. Преподаватель видит всех с настоящими именами.
- **Споры.** Студент оспаривает своё начисление или применённый переход. Преподаватель отвечает: принятый спор о начислении может добавить баллы с причиной из ответа, принятый спор о переходе отменяет его. Ручное начисление тоже требует причины.
- **Фоновый пересчёт.** Раз в минуту сервер пересчитывает лиги активных курсов. Каждое открытие лиги тоже пересчитывает её.
- **Что дальше.** Задачи от вуза и партнёров, награды, дополнительные квоты GPU по дивизионам и отметка ИИ о похожих проектах войдут в следующую часть.
