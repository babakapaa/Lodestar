# 0049. Вход из LMS по LTI 1.3

Дата: 2026-11-13. Статус: принято.

## Решение

- **Ядро `core/lti`.** LTI нужен любому вузу с LMS, поэтому он в ядре, а не в модуле. Право на настройку: `core.integrations.manage`.
- **Площадки.** Администратор подключает LMS: издатель, client_id, адреса входа, токенов и ключей, список deployment_id. Lodestar показывает свои адреса для регистрации в LMS (`GET /v1/lti/tool`). Ключ инструмента RSA 2048 создаётся сам для каждого вуза и хранится зашифрованным.
- **Вход.** `/v1/lti/tenants/{tenant}/login` начинает вход по OIDC, `/launch` проверяет id_token по ключам LMS: издатель, аудитория, azp, nonce, срок, deployment_id, тип сообщения `LtiResourceLinkRequest` и версия 1.3.0. State одноразовый и живёт столько же, сколько обычный вход.
- **Кто вошёл.** Пользователь LMS связывается с аккаунтом Lodestar навсегда при первом входе. Узнавать существующий аккаунт по почте можно только если вуз включил это для площадки: почту в LMS может поменять её администратор. Иначе создаётся новый аккаунт.
- **Билет вместо токена в адресе.** После проверки сервер выдаёт одноразовый билет на 1 минуту и переводит браузер в приложение на `/lti?ticket=…&next=…`. Приложение меняет билет на сессию через `POST /v1/auth/token` с `grantType: launch_ticket`. Токены доступа в адрес не попадают.
- **Курс LMS.** Каждый запуск сохраняет курс LMS (адреса NRPS и AGS на будущее) и роль человека в нём. Преподавателем считается роль Instructor, Administrator или ContentDeveloper курса.
- **Привязка.** Модули отдают то, к чему можно привязать курс LMS, через `module.LinkSource` (вид с именем модуля). Учёба отдаёт `study.course`: курсы, которые человек ведёт. Привязать может только преподаватель курса в LMS, который ведёт и курс Lodestar. После привязки запуск сразу открывает курс Lodestar, без привязки открывается экран курса LMS.
- **Пока не делаем.** Списки NRPS, оценки AGS и источник заданий курса будут в 8b. Deep Linking позже.
