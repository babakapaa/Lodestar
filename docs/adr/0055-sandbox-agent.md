# 0055. Агент GPU-узла

Дата: 2026-11-13. Статус: принято.

## Решение

- **Отдельная программа `lodestar-agent`.** Она ставится на каждую GPU-машину вуза рядом с Docker и NVIDIA Container Toolkit. Агент раз в 10 секунд сверяется с сервером (ADR 0054) и приводит контейнеры к плану. Вузу не нужен Kubernetes. Если он у вуза есть, агента можно запустить и там.
- **Docker Engine API напрямую.** Агент говорит с Docker через сокет по HTTP API v1.43, без SDK. Зависимостей меньше, а набор нужных вызовов маленький: список, создание, запуск, остановка, удаление, загрузка образа.
- **Одна карта на запуск.** Номер карты агент хранит в метке контейнера и передаёт его через `DeviceRequests` с `DeviceIDs`. Поэтому после перезапуска агента карты не путаются.
- **Папка владельца.** Сервер присылает `workspace` (`user-<id>` или `team-<id>`). Агент монтирует `LODESTAR_AGENT_DATA/<workspace>` в `/workspace`. Файлы и точки сохранения переживают запуски, а запуски команды видят общую папку. Имя папки проверяется по шаблону, чтобы нельзя было выйти за `LODESTAR_AGENT_DATA`.
- **Сеансы.** Jupyter запускается как `jupyter lab` с одноразовым токеном. VS Code в браузере запускается как `openvscode-server` с `--connection-token`. Поэтому в образе окружения для этих видов должна быть нужная программа. Адрес сеанса строится из `LODESTAR_AGENT_HOST` и порта, который выдал Docker. Фоновая задача запускается как `sh -c <команда>`.
- **Сверка, а не команды.** Контейнер, которого нет в плане, удаляется. Контейнер с `stop` останавливается. Завершённый контейнер один раз попадает в отчёт с кодом выхода, после этого сервер убирает запуск из плана. Если сервер недоступен, агент ничего не трогает и пробует снова.

## Настройка

`LODESTAR_SERVER`, `LODESTAR_NODE_TOKEN` (выдаётся при добавлении узла), `LODESTAR_AGENT_GPUS`, `LODESTAR_AGENT_HOST`, `LODESTAR_AGENT_SCHEME` (по умолчанию http), `LODESTAR_AGENT_DATA` (по умолчанию `/var/lib/lodestar-agent`), `LODESTAR_AGENT_EVERY` (по умолчанию 10s), `DOCKER_HOST` (по умолчанию сокет Docker).
