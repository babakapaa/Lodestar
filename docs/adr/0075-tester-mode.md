# 0075. Режим тестировщика

Дата: 2026-11-14. Статус: принято.

## Решение

- **Зачем.** Чтобы погонять Lodestar самому, без настоящего входа вуза, без отдельного демо-входа и без ручного `lodestarctl demo seed`.
- **Как включить.** `LODESTAR_TESTER_MODE=on`. При старте сервер сам заводит тестовый вуз `demo` с курсом «Основы биологии» и людьми: студентка, студент, преподаватель и администратор. Повторный старт ничего не дублирует.
- **Демо-вход внутри сервера.** Тот же `demoidp` открыт по адресу `/tester/idp`, издатель `LODESTAR_PUBLIC_URL/tester/idp`. Сервер ходит к нему не по сети, а напрямую, поэтому не нужен второй порт и адрес, который видно и с телефона, и из контейнера. Кнопка «Войти через Демо-вход» проходит весь путь OIDC, как у настоящего вуза.
- **Быстрый вход.** `GET /v1/tester` отдаёт код вуза и список людей, `POST /v1/tester/sign-in` сразу выдаёт пару токенов за выбранного человека. Без режима этих путей нет, сервер отвечает 404. Вход только в вуз `demo`.
- **Приложение.** Если сервер в режиме тестировщика и указан вуз `demo`, на экране входа есть раздел «Режим тестировщика» с кнопкой на каждого человека. В профиле тот же раздел меняет пользователя: выход, очистка локальных заметок и чатов, вход за другого.
- **Веб с сервера.** `LODESTAR_WEB_DIR` указывает на сборку `flutter build web`. Сервер отдаёт файлы оттуда, а на любой другой путь вне `/v1/`, `/healthz` и `/readyz` отдаёт `index.html`, чтобы работали адреса приложения.
- **Обвязка.** `deploy/tester.yaml` поверх `compose.yaml`: режим, веб из `app/build/web` и Mailpit, чтобы видеть письма в браузере. Команда `make tester`.
- **Безопасность.** Режим пускает кого угодно без пароля. Сервер пишет предупреждение в журнал при каждом старте. У настоящего вуза режим не включают.
